# prime — заправка контекстом

Цель: за один проход «впитать» документацию DankoDeploy и текущее состояние репозитория,
а затем выдать пользователю сжатую сводку, с которой можно сразу работать. Скилл **только читает**
(никаких правок кода/доков).

## Что делать

Выполни шаги по порядку. Чтение независимых файлов делай **параллельно** (в одном блоке вызовов).

### 1. Документация (источник правды)

Прочитай в этом порядке — это иерархия проекта (см. [CLAUDE.md](../../../CLAUDE.md)):

1. [AGENTS.md](../../../AGENTS.md) — **свод правил** для агентов: стек, карта репозитория, команды,
   правила кода, безопасность (критично!), проверка результата, подводные камни.
2. [docs/CODEMAP.md](../../../docs/CODEMAP.md) — плоский индекс «путь → назначение» + навигация
   по сценариям («хочу сделать X — смотри сюда»).
3. [docs/ARCHITECTURE.md](../../../docs/ARCHITECTURE.md) — полный контекст архитектуры (§-разделы).
   Большой файл: прочитай оглавление и §-разделы, релевантные текущей задаче (если задача задана).
   Без конкретной задачи — пройдись по структуре, не зачитывай целиком.

Если переданы аргументы (`/prime <тема>`) — трактуй их как фокус: после общей карты углубись
в соответствующие §-разделы ARCHITECTURE.md и строки CODEMAP.md по этой теме.

Прочие доки читай **только если релевантны**: `docs/DEPLOY.md` (раскатка панели на VPS),
`docs/SERVICE-SPEC.md` (формат `config` проектов), `README.md`.

### 2. Состояние репозитория

Собери актуальное состояние (документация может отставать от кода):

- `git log --oneline -15` — последние коммиты (над чем шла работа).
- `git status` — незакоммиченные изменения.
- `git branch --show-current` — текущая ветка.

### 3. Сверка и сводка

Выдай пользователю **краткую** сводку (не пересказ доков целиком):

- **Что за проект** — 1–2 предложения.
- **Текущее состояние** — ветка, последние коммиты, есть ли незакоммиченные изменения.
- **Ключевые правила**, которые легко нарушить (ESM-импорты с `.js`, типы сначала в `packages/shared`,
  `shellQuote` для пользовательского ввода в shell, не утекать detail ошибок в 5xx, `pnpm db:push`
  вместо миграций, проверки `typecheck`/`lint`/`test` перед завершением).
- **Куда смотреть** под текущую задачу (если задана в аргументах) — конкретные файлы из CODEMAP.

Если заметил **расхождение доков с кодом** (упомянутый файл не существует, переименован и т.п.) —
отметь это явно: документация — источник правды, но её держат в синхроне вручную, и она может отстать.

## Чего НЕ делать

- Не зачитывай содержимое файлов дословно — пользователь их и так видел. Давай выжимку.
- Не правь код, доки или конфиги — это read-only заправка.
- Не запускай `pnpm install`/`dev`/`build` — только git-команды для чтения состояния.
