# ⚡ DankoDeploy

Веб-панель для управления своими сервисами на VPS: деплой «по кнопке», мониторинг,
бэкапы и сводка по проектам — всё через SSH, **без агентов** на серверах.

> **Документация:** [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — полный контекст и устройство ·
> [docs/SERVICE-SPEC.md](docs/SERVICE-SPEC.md) — как подготовить свои сервисы к деплою ·
> [CLAUDE.md](CLAUDE.md) / [AGENTS.md](AGENTS.md) — инструкции для AI-агентов.

## Возможности

- **Деплой по кнопке** — `git pull` + `docker compose up`, `systemctl restart` или
  произвольные шаги; live-лог деплоя стримится в браузер по WebSocket.
- **Мониторинг** — CPU / RAM / диск / docker-контейнеры серверов в реальном времени
  (собирается по SSH одной командой).
- **Бэкапы** — вручную и по cron-расписанию; результат скачивается на машину панели.
- **Сводка по проектам** — статус, стек, git-ревизия, последний деплой.
- **Терминал сервера** — прямой SSH shell в браузере из вкладки «Серверы».
- **AI-агенты** — разворачивает Claude Code / Codex на сервере (в tmux) и даёт живой
  веб-терминал прямо в браузере, в т.ч. с телефона.
- **SSH-ключи** — генерация, импорт, развёртывание на серверы; приватники шифруются.
- **Аутентификация панели** — вход по паролю (опционально; обязателен перед выносом наружу).

## Стек

| Слой | Технология |
|------|-----------|
| Backend | Node + TypeScript + Fastify + `@fastify/websocket` + `@fastify/cookie` |
| SSH / PTY | `node-ssh` (ssh2) — exec, стрим логов, интерактивный shell для веб-терминала |
| БД | SQLite + Drizzle ORM |
| Секреты | AES-256-GCM (`node:crypto`), мастер-ключ из env |
| Аутентификация | scrypt-хэш пароля + подписанная httpOnly cookie |
| Планировщик | `node-cron` |
| Frontend | React + Vite + Tailwind + TanStack Query + Recharts + xterm.js |
| Общие типы | Zod (`packages/shared`) |

## Структура

```
apps/
  server/   # Fastify API + WS + SSH-движок + планировщик
  web/      # React-дашборд
packages/
  shared/   # Zod-схемы и типы (источник истины)
  db/       # Drizzle schema + миграции (SQLite)
  core/     # SshExecutor, DeployRunner, MetricsCollector, BackupRunner
```

## Быстрый старт (локально)

```bash
# 1. Установить зависимости (нужен Node >= 20)
corepack enable
pnpm install

# 2. Создать .env (см. .env.example) и сгенерировать мастер-ключ:
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
cp .env.example .env   # затем вписать DANKODEPLOY_MASTER_KEY и абсолютный DATABASE_URL

# 3. Создать схему БД
pnpm db:push          # применяет schema.ts напрямую (для разработки)

# 4. (опционально, но обязательно перед выносом наружу) задать пароль панели
pnpm gen-password     # выведет DANKODEPLOY_AUTH_PASSWORD_HASH=... и SESSION_SECRET=... — вставьте в .env

# 5. Запустить backend и frontend
pnpm dev
# server: http://127.0.0.1:3001   web: http://localhost:5173
```

Откройте http://localhost:5173 (если задан пароль — войдите), добавьте сервер на вкладке
**Серверы**, нажмите **Test connection**, затем заведите проект и жмите **Deploy**.

## Пароль для входа в панель

По умолчанию (без `DANKODEPLOY_AUTH_PASSWORD_HASH`) панель работает **без логина** — это
удобно для локальной разработки, но небезопасно. Чтобы включить вход по паролю:

```bash
pnpm gen-password            # спросит пароль интерактивно
# или передать аргументом:
pnpm gen-password "мой-пароль"
```

Команда выведет две строки — вставьте их в `.env` и перезапустите сервер:

```
DANKODEPLOY_AUTH_PASSWORD_HASH=<scrypt-хэш>
DANKODEPLOY_SESSION_SECRET=<секрет для cookie>
```

После этого панель потребует пароль при входе. **Это обязательно перед тем, как открывать
панель из интернета** (веб-терминалы серверов и AI-агентов = прямой доступ к shell сервера).

## Работа с БД

Схема описана в [`packages/db/src/schema.ts`](packages/db/src/schema.ts).

- **В разработке** правь `schema.ts` и применяй изменения напрямую: `pnpm db:push`
  (без генерации миграций; данные в dev-БД не священны).
- **Просмотр данных:** `pnpm db:studio` (Drizzle Studio).
- **Для продакшена**, когда понадобится версионирование: `pnpm db:generate` (создаёт SQL-миграцию)
  + `pnpm db:migrate` (применяет). Сгенерированные миграции **проверяй глазами** —
  drizzle-kit при пересоздании SQLite-таблицы иногда ошибается.

## Запуск в Docker

```bash
# .env должен содержать DANKODEPLOY_MASTER_KEY
docker compose up --build
# панель доступна только на 127.0.0.1:3001 (фронт собирается отдельно: pnpm --filter @dankodeploy/web build)
```

## Развёртывание на VPS

Для выноса панели наружу (HTTPS + обязательный пароль) весь комплект раскатки — в каталоге
[`deploy/`](deploy/): Docker Compose (`server` + `web`/nginx со статикой фронта и проксированием
`/api`,`/ws`) за общим **Traefik** (авто Let's Encrypt). Пошаговая инструкция и чек-лист
безопасности — в [docs/DEPLOY.md](docs/DEPLOY.md).

**Раскатка одной командой (Ansible):** [`deploy/ansible/`](deploy/ansible/) — Ansible сам ставит
Docker, поднимает Traefik (если его нет) и сеть `web`, тянет код, генерит секреты и поднимает стек.
Вы заполняете минимум (адрес VPS, домен, repo, email, пароль панели) и запускаете
`ansible-playbook site.yml`. Деплой независим от состояния VPS.

> ⚠️ Веб-терминалы = прямой shell к вашим серверам. Перед публикацией наружу **обязателен**
> пароль панели (`pnpm gen-password`) и TLS; порт `3001` напрямую не публикуется.

## Конфигурация проекта

Серверы и проекты заводятся через UI (хранятся в SQLite). Структуру `config`
проекта и примеры для разных типов сервисов см. в
[`dankodeploy.config.example.yaml`](./dankodeploy.config.example.yaml).

📋 **Как подготовить свой проект к деплою** (требования к репозиторию, раскладка на сервере,
чек-лист, антипаттерны) — см. [docs/SERVICE-SPEC.md](docs/SERVICE-SPEC.md).

Ключевые поля `config`:
- `workdir` — рабочая директория на сервере;
- `composeFile` / `systemdUnit` — для соответствующих типов;
- `deploySteps` — переопределить дефолтные шаги деплоя;
- `backupCommand` — команда бэкапа (`{{OUT}}` подставляется путём к файлу);
- `backupCron` — cron-выражение для авто-бэкапов.

## AI-агенты (Claude Code / Codex)

Вкладка **AI** разворачивает AI-кодинг-агента на выбранном сервере и даёт к нему живой
веб-терминал в браузере (в т.ч. с телефона):

1. **Развернуть агента** — выбираешь сервер, тип (Claude Code / Codex) и рабочую директорию.
   Панель по SSH ставит CLI и `tmux`, запускает агента в tmux-сессии (`dd-agent-<id>`).
2. **Терминал** — открывает интерактивный shell к этой tmux-сессии прямо в браузере
   (xterm.js поверх SSH pty). Печатаешь команды агенту как в обычном терминале.
3. **Авторизация агента** — при первом запуске Claude Code/Codex показывает ссылку для входа
   прямо в веб-терминале; логинишься один раз, токены остаются на сервере и переживают
   перезапуск. `Стоп` гасит процесс, но не разлогинивает.
4. **Удалить с сервера** — останавливает tmux-сессию и удаляет CLI агента с VPS через
   `npm uninstall -g`; запись в панели остаётся, чтобы агента можно было поставить повторно.

Требования на сервере: `npm`/Node (для установки CLI) и доступ к `tmux` (ставится автоматически
при наличии apt/dnf/yum/apk/brew). tmux держит сессию живой — закрыл вкладку, агент продолжает;
открыл с телефона — тот же экран.

> ⚠️ Веб-терминалы = **прямой shell-доступ к серверу**. Включай пароль панели
> (`pnpm gen-password`) и работай за HTTPS, прежде чем открывать панель наружу.

## Безопасность

- SSH-ключи и пароли шифруются **AES-256-GCM**; в БД лежит только шифротекст.
  Мастер-ключ (`DANKODEPLOY_MASTER_KEY`) хранится в env и **не коммитится** —
  без него сохранённые доступы не расшифровать.
- **Аутентификация панели** — вход по паролю (scrypt-хэш в env), сессия в подписанной
  httpOnly cookie. WS-соединение (включая терминал) проверяет сессию на handshake.
  Без `DANKODEPLOY_AUTH_PASSWORD_HASH` аутентификация выключена (только для локального dev).
- Панель по умолчанию слушает `127.0.0.1` — наружу не торчит. Для доступа снаружи —
  за reverse-proxy с TLS (nginx), не публикуй порт `3001` напрямую.
- `.env`, `*.sqlite`, `backups/`, `dankodeploy.config.yaml` — в `.gitignore`.
